## 1. Executive Strategy: Retrieval-First Continuous Improvement

In classical philology and dialectal computational linguistics, **unsupervised automated model-weight training is dangerous**. Automatically updating neural weights from raw, crowdsourced user feedback leads to:
1. **Dialectal and Stylistic Contamination:** Colloquial dialect words contaminating Classical Arabic (*Fusha Turathiya*) grammatical generation.
2. **Pedagogical Hallucination Ingestion:** Well-meaning but linguistically incorrect user "corrections" degrading model precision.
3. **Catastrophic Forgetting:** Fine-tuning on sparse correction sets destroying global morphological conjugation and syntactic parsing.

### The Peregrine Continuous Improvement Paradigm
Peregrine adopts a **Retrieval-First Learning Pipeline**:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                 PEREGRINE CONTINUOUS LEARNING DATA FLOW                     │
│                                                                             │
│  [User Feedback / Correction]                                               │
│                 │                                                           │
│                 ▼                                                           │
│  [1. Ingress & Provenance Capture] (Raw text, harakat, dialect tags)        │
│                 │                                                           │
│                 ▼                                                           │
│  [2. Automated Verification Gate] (Deterministic validation via PyArud/NLP) │
│                 │                                                           │
│                 ▼                                                           │
│  [3. Scholarly Triage Queue] (Opinion vs. Fact; Basran/Kufan arbitration)  │
│                 │                                                           │
│        ┌────────┴──────────────────────────┐                                │
│        ▼                                   ▼                                │
│  [Approved Corrections]              [Rejected / Disputed]                  │
│        │                                   │                                │
│        ▼                                   ▼                                │
│  [Curated Knowledge Store]           [Contrastive Negative Store]           │
│  (Indexed into Vector & Lexical RAG) (Used for Philological Evaluation)     │
│        │                                                                    │
│        ▼                                                                    │
│  [Dynamic Few-Shot Injection] ──► Instant Model Improvement in Beta V-001   │
│  (Zero Model Weight Retraining)                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

1. **Immediate Value (Beta V-001):** Verified corrections are promoted to the **Curated Knowledge Base** (vector embeddings + exact lexical inverted index). During live tutoring and analysis, the agent dynamically retrieves these verified exemplars as high-priority context and few-shot guidance.
2. **Future Research Value (Post-Beta):** Accumulated, double-verified linguistic corpora are packaged into versioned, licensed datasets for future supervised fine-tuning (SFT) and Direct Preference Optimization (DPO).

## 2. Ingress & Correction Capture Mechanisms

Feedback is captured across three explicit user touchpoints:

### 2.1 Capture Touchpoints
1. **Interactive Chat Correction (Tutor / Speaking Partner):**
   - User highlights a specific word, phrase, or explanation and selects `"Suggest Correction"`.
   - UI captures:
     - `original_prompt`: The user's input.
     - `model_generation`: The exact text generated by Peregrine.
     - `proposed_correction`: The user's replacement text.
     - `rationale`: Optional explanation in Arabic or English.
     - `dialogue_mode`: e.g. `"classical_poetry"`, `"emirati_conversation"`, `"grammar_tutor"`.
2. **Explicit Evaluation Grading:**
   - Thumbs up/down on specific linguistic cards (e.g. Prosody Scansion Card, Conjugation Table, Root Breakdown).
   - Selection of structured error tags: `Incorrect Harakat`, `Wrong Meter`, `Hallucinated Root`, `Non-Emirati Vocabulary`, `Syntactic Error (I'rab)`.
3. **Expert Scholarly Submission Portal:**
   - Dedicated interface for partner universities and certified Arabic scholars (*Asatidhat al-Lugha*) to submit verified classical poetry scansions, dialectal phrasebooks, and grammatical parsing trees.

## 3. Disambiguating Customer Opinions from Linguistic Facts

A primary vulnerability of language platforms is accepting user preference as objective grammatical truth. Peregrine implements a **Three-Tier Triage Filter**:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                       3-TIER VERIFICATION & TRIAGE ENGINE                   │
│                                                                             │
│  [Incoming Submission]                                                      │
│           │                                                                 │
│           ▼                                                                 │
│  ┌───────────────────────────────────────────────────────────────────────┐  │
│  │ Tier 1: Deterministic Engine Verification                             │  │
│  │ - Prosody: Tested against PyArud 1.0.0 scansion.                      │  │
│  │ - Morphology: Tested against standard root templates.                 │  │
│  │ - Normalization: Checked for Unicode validity and vowel density.      │  │
│  └──────────────────────────────────┬────────────────────────────────────┘  │
│                                     ▼                                       │
│  ┌───────────────────────────────────────────────────────────────────────┐  │
│  │ Tier 2: Scholarly Disambiguation (Fact vs. Opinion)                  │  │
│  │ - Is it an objective rule violation? (e.g. wrong case ending)        │  │
│  │ - Is it a legitimate classical dispute? (Basran vs. Kufan school)    │  │
│  │ - Is it prescriptive purism attacking authentic dialect speech?      │  │
│  └──────────────────────────────────┬────────────────────────────────────┘  │
│                                     ▼                                       │
│  ┌───────────────────────────────────────────────────────────────────────┐  │
│  │ Tier 3: Scholarly Human Review Queue                                  │  │
│  │ - Conflicting submissions routed to 2 certified philologists.        │  │
│  │ - Mandatory consensus before promoting to Gold Retrieval Store.       │  │
│  └───────────────────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 3.1 Categorization Rules

#### A. Objective Grammatical Facts (Automatic or Fast-Path Approval)
- Mathematical scansion mismatches (e.g., user points out that a foot is `مَفَاعِلُنْ` instead of `مَفَاعِيلُنْ`, confirmed deterministically by PyArud).
- Definitive grammatical errors (e.g., accusative case after *Inna* violated: `"إنَّ زيدٌ"` $\rightarrow$ `"إنَّ زيداً"`).
- Incorrect triliteral root derivation (e.g., claiming root of `"ميزان"` is `"مزن"` instead of `"وزن"`).

#### B. Classical Dialectical / School Disputes (*Ikhtilaf al-Nahwiyyin*)
- Disagreements between the **Basran School (*Al-Madrasa al-Basriyya*)** and **Kufan School (*Al-Madrasa al-Kufiyya*)** (e.g. governance of *Ism al-Fa'il*, permissibility of specific poetic licenses).
- **Policy:** **NEVER** mark either school as "wrong". The system creates an `opinion_school` metadata tag, categorizing the variant as `"Basran Tradition"` or `"Kufan Tradition"`, enriching the model's scholarly depth.

#### C. Prescriptive Dialect Purism (Rejection)
- When a user flags authentic Emirati colloquial vocabulary (e.g., `"وايد"` or `"شحالك"`) during a Rashid/Maryam conversation and demands it be changed to MSA (`"كثيراً"` or `"كيف حالك"`).
- **Policy:** **REJECTED.** Tagged as `"dialect_prescriptivism"`. The system protects dialect integrity in conversational speaking partner contexts.

## 4. Multi-Dimensional Linguistic Taxonomy

Every captured data record is categorized across two orthogonal axes: **Language Variety** and **Linguistic Sub-Discipline**.

### 4.1 Language Variety Stratification (`language_variety`)
1. **Classical Arabic / Heritage (`classical_fusha`):** Quranic Arabic, Pre-Islamic (*Jahiliyya*), Umayyad, Abbasid, and Andalusian literary corpora. Strictly requires full vocalization (*I'rab* and *Sarf*).
2. **Modern Standard Arabic (`msa`):** Formal contemporary written and broadcast Arabic (UN, media, academia, legal).
3. **Emirati Gulf Arabic (`emirati_colloquial`):** Spoken vernacular of Abu Dhabi, Dubai, Sharjah, and Northern Emirates. Characterized by specific phonology ($j \rightarrow y$, $q \rightarrow g$), vocabulary (`رمسة`, `طَرَش`, `باجر`), and syntax.
4. **Other Regional Dialects (`other_dialect`):** Levantine (`levantine`), Egyptian (`egyptian`), Maghrebi (`maghrebi`), Najdi/Hejazi (`saudi_gulf`).

### 4.2 Linguistic Sub-Discipline Labelling (`linguistic_domain`)
- **`nahw` (Syntax):** Case endings (*I'rab*), governance (*'Amal*), sentence structure (*Jumlah Ismiyya/Fi'liyya*).
- **`sarf` (Morphology):** Verb forms (Forms I–X), weak verbs, roots, augmentations (*Awzan*), broken plurals.
- **`balagha` (Rhetoric):** *'Ilm al-Ma'ani* (semantics), *'Ilm al-Bayan* (metaphor, simile, metonymy), *'Ilm al-Badi'* (antithesis, paronomasia, rhymed prose).
- **`arud` (Prosody):** The 16 Farahidian meters, metric variations (*Tam*, *Majzoo*), *Zihaf* and *'Ilal* alterations.
- **`qafiyah` (Rhyme):** *Rawi*, *Wasl*, *Ridf*, *Ta'sis*, *Dakhil*, rhyme vowels (*Majra*), and defects (*'Uyub al-Shi'r*).
- **`adab` (Literature & Lexicography):** Classical diwan attribution, historical context, archaic lexicon (*Gharib al-Alfaz*).
- **`sawt` (Phonetics & Pronunciation):** Consonant articulation points (*Makharij al-Huruf*), pharyngealization, Gulf colloquial phonetic shifts.

## 5. Text Preservation & Provenance Architecture

To prevent data corruption, every record maintains an immutable record of its evolution:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                         MULTI-LAYER TEXT REPRESENTATION                     │
│                                                                             │
│   1. original_text        Raw, unmodified customer string as submitted      │
│   2. nfc_text             Canonical Unicode composition (combining marks)   │
│   3. vocalized_text       Fully diacritized Arabic string (Harakat)         │
│   4. unvocalized_text     Cleaned string with Tashkeel and Tatweel stripped │
│   5. arudi_text           Phonetic representation for scansion (if poetry)  │
└─────────────────────────────────────────────────────────────────────────────┘
```

### Provenance Tracking
Every record captures:
- `contributor_id`: Anonymized user ID.
- `contributor_tier`: `student`, `educator`, `native_speaker`, `certified_scholar`.
- `source_context`: URL, book reference, diwan citation, or conversation session ID.
- `license_agreement`: Confirmation that submission is released under CC-BY-SA 4.0 or platform internal training license.

## 6. Scholarly Human Review Queue & Conflict Resolution

Submissions that cannot be deterministically validated by PyArud or rule-based normalizers are queued for human scholarly review.

### 6.1 Review Triage States
1. `pending_triage`: Initial submission awaiting automated filtering.
2. `in_scholarly_review`: Assigned to the expert review pool.
3. `approved_gold`: Dual-verified by two independent certified scholars. Promoted immediately to the RAG Knowledge Base.
4. `approved_dialect`: Validated as authentic colloquial variation. Added to the Speaking Partner dialect lexicon.
5. `disputed_valid_variant`: Recognized as an alternate valid classical school reading (*Wajh Ja'iz*).
6. `rejected_error`: Linguistically erroneous suggestion. Archived into the negative test suite.
7. `rejected_opinion`: Subjective stylistic preference that does not constitute a grammatical error.

### 6.2 Reviewer UI & Evaluation Rubric
Scholars review records via a clean, web-based curation drawer displaying:
- Left Pane: Original student prompt and Peregrine's generation.
- Middle Pane: User's proposed correction with highlighted character/harakat diffs.
- Right Pane: Deterministic engine telemetry (PyArud scansion, vowel density, morphological patterns).
- Action Buttons: `Approve as Gold`, `Approve as Dialect`, `Mark as Scholarly Disputed`, `Reject`.

## 7. Dataset Packaging, Versioning & Permissions

Approved records are compiled into versioned, immutably signed evaluation and retrieval datasets:

### 7.1 Dataset Artifact Structure
```
datasets/
├── v1.0.0-beta/
│   ├── manifest.json                     # Release metadata, SHA256 checksums, licenses
│   ├── nahw_verified_cases.jsonl         # Syntax & I'rab corrections
│   ├── sarf_paradigms.jsonl              # Verified root & conjugation cases
│   ├── arud_canonical_verses.jsonl       # Poetic verses with gold Farahidian scansion
│   ├── emirati_lexicon_approved.jsonl    # Colloquial vocabulary & dialogues
│   └── contrastive_negative_cases.jsonl  # Known student errors & rejected hallucination pairs
```

### 7.2 Strict Train / Validation / Test Splitting
- To prevent data contamination during future fine-tuning, every record is deterministically assigned a persistent split hash:
  $$\text{SplitHash} = \text{SHA256}(\text{record\_id} + \text{"peregrine\_seed\_2026"}) \pmod{100}$$
  - $0 \le \text{Hash} < 80 \implies \textbf{Train}$ (Future fine-tuning / Few-shot candidate)
  - $80 \le \text{Hash} < 90 \implies \textbf{Validation}$ (Hyperparameter tuning)
  - $90 \le \text{Hash} < 100 \implies \textbf{Test}$ (Immutably locked gold benchmark)
